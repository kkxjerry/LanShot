# LanShot 反问模式 Gold Answer v1

来源：`/Users/zhouguichao/Desktop/面试分析/面试记录`

这份文件不是 Prompt，而是后续调 Prompt 的目标答案。每场面试只保留 2～3 个真正值得问的问题。核心标准不是“我哪题没答好”，而是：这个问题能不能从当前面试官那里换回高价值、可复用的信息。

## 目标输出应该长什么样

最终悬浮窗不需要展示“P0 必杀级、P1 真知级”这类标签，也不需要长篇解释。推荐只展示三条：

1. 最值得问：一条最贴本场上下文的问题。
2. 第二选择：补一个工程取舍、业务瓶颈或评价依据。
3. 备选：岗位职责或验收标准。

每条问题本身尽量控制在 1～2 句话。内部可以保留 reason/evidence 供排序，但不要全部展示给用户。

## 从真实面试得到的关键结论

09-18 TL 面证明，最高价值问题不一定来自“候选人答错”。“您从哪些表述判断我偏研究、工程落地不足？”直接换回了 PR、Code Review、部署发版、边界、成本、P99 延迟、可用性等一整套反馈，这类“评价依据校准”应该进入最高优先级。

09-07 政企面说明，面试官连续追问某个工程边界时，最适合反问的是他的真实实现取舍。例如代码编辑到底用文本 patch、AST/LSP 还是唯一性强校验，以及副作用操作超时以后如何做幂等。

09-10 工业资源平台和 09-16 两场业务面说明，面试官突然给出很具体的数据规模、业务对象或约束时，优先判断它是不是团队真实问题，并继续问当前瓶颈、本人负责哪段、最终怎么验收，而不是退回到“团队规模多大”。

09-18 AI 教育面说明，面试官自己给出明确技术观点时，不要马上和他争论。把观点改造成可验证问题，例如 Tool Calling 成功率到底按工具选择、参数正确还是端到端任务完成来算；不超纲和内容溯源又如何评测。

## 运行时禁止项

不要直接说“我刚才答得不好，所以想问……”。必要时只用“刚才您问到……”自然承接。

不要直接问“如果是您，这道题会怎么回答”。更自然的是问真实项目中怎么做、为什么这么取舍、怎么验收。

不要重复已经得到答案的事实。例如对方已经讲完 9B + SFT/DPO + RAG，就不要再问“你们用什么模型、做什么业务”。

不要一次抛 5 个子问题。一个问题只拿一个核心信息，必要时根据面试官回答再现场追问。
