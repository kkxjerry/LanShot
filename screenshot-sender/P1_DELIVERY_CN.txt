LanShot P1 修订审计与完整交付说明
版本：lanshot-p1r2-20260908.1
修订日期：2026-09-08

一、这次到底改了什么

这次修改的是上传的 LanShot_P1_实现与测试包_2026-09-07.zip 的工作副本，并从更早的用户源码 ZIP 恢复原生显示源码。不是在用户 Mac 当前 P0 目录直接打补丁。

正式显示端恢复为 CaptureExclusionDemo 原生窗口；删除替代它的 Tk GUI。
新增统一显示桥接，使本地/远程结果、翻页命令和显示回执落在明确配置的同一显示目录。
新增内嵌接收路径、本地双 HTTP 接收服务以及可选远程 HTTPS 接收服务；同一任务不会向多个独立模型处理端同时群发。
保留 P1 的可靠队列、明确状态、重试预算、持久确认、诊断脱敏、进程管理和迁移保护。

原始两个 ZIP 不变，用户截图、Keychain、运行数据库、配置和本机源码均未删除。没有在用户 Mac 或真实远程服务器部署，没有提交到用户的 develop。
容器工作区建立了 develop 基线，仅用于审计差异，不是用户仓库提交。当前 Mac 最新 P0 与本包仍未逐文件合并验收。
本轮只能发现 DevSpaces 的工具定义，没有获得可执行的本机文件操作能力；不能把“发现工具定义”写成“已经执行了远程读写”。

二、原 P1 中确认的问题

1. start_assessment.command 不再打开原生 App。start_written.command 与它采用同样的启动逻辑，没有保持原来的模式差异。
2. P1 将结果写到 LanShotP1/receiver，而原生窗口仍固定读取旧 ~/.local/share/lanshot-receiver。
3. sender 的翻页命令仍默认写旧 page.txt；答案与控制信号不在同一状态目录。
4. 包中没有原生 App 的源码接入和编译验收，却加入 Tk GUI 作为显示入口。
5. 单个接收实例的生命周期与 HTTP 进程耦合；不能直接以多个独立实例各持台账的方式安全替换。
6. 多开实例若仍各自恢复 processing 任务，会把另一存活实例正在执行的模型请求误判为崩溃恢复。
7. 原始 P1 报告、旧 patch 和校验文件不再适用于此次修订，必须重新生成，不能沿用之前的136项结论。

四、现在的运行结构

F22/原生菜单/CLI 请求
→ 截图与脱敏
→ 本地持久发送队列
→ 按顺序选择接收入口
→ 持久接收状态与模型处理
→ 按原任务归属读取结果
→ display_bridge
→ CaptureExclusionDemo 原生显示

正常优先级为 embedded → local-primary → local-backup → 可选 remote。

embedded：接收逻辑与 sender 在同一进程中复用，不绕 localhost HTTP，也没有启动一个假的自接收网络循环。
local-primary / local-backup：两个独立 HTTP 服务，默认 8788 和8789，与 embedded 共享本机接收数据库和执行锁。
remote：独立机器上的 HTTPS 接收服务，独立认证令牌、独立数据库，默认不启用。

必须区分“选择哪个入口提交”与“哪个本地进程真正执行模型”。本地实例共用分析队列，只有 analysis-owner.lock 的持有者执行模型。冗余模式下，任务可以通过 embedded 入队，但由已经取得执行锁的本地 HTTP 实例处理。monolith 模式才明确在 sender 的内嵌运行时中执行。
单体模式没有 localhost HTTP 接收进程，保留独立显示桥接和原生窗口。它消除本机 HTTP 依赖，但不保留同进程崩溃隔离。
冗余模式启动 receiver、receiver_backup、sender、display 四个托管角色；sender 中另含 embedded 运行时。原生 App 是显示进程，不是第三个模型。

五、多服务可靠性与切换规则

一个任务始终保留 ID、图片摘要、origin、origin_seq、profile、created、expires，以及固定路由策略。
发送前把 backend、cluster_id、摘要和状态写入发送端同一数据库。发送端领取租约过期后，旧工作者不能继续更改任务归属。

允许切换的情况：尚未提交；健康检查未通过；明确连接被拒绝、域名解析失败等确定未送达的连接阶段故障。
不能直接换独立集群的情况：POST 超时、5xx、确认缺少字段/不匹配、响应丢失，以及模型已启动但结果未知。
这些情况下查询原 cluster；原主端口不通，可以访问共享同一数据库的备用端口。独立远程集群不是原集群的证明来源。
结果校验包含任务 ID、图片摘要、profile、来源和序号；返回其他任务的答案会被拒绝。
配置变化产生新的 queue_target 摘要，不会静默把旧截图发往新增服务器。旧队列需要保留旧策略恢复或显式处理。
连续失败触发短熔断，避免每轮耗尽时间；总操作预算覆盖多入口探测，租约和心跳不能仍按单个请求时间估计。

本地分析执行锁由真正工作的线程持有直到线程退出。关闭 HTTP 服务但模型线程尚未退出时，不会提前交锁给另一个实例。
所有者进程真正退出后，备用实例接手 queued 任务；遗留 processing 标为 uncertain，不直接再次调用模型。
同一集群重复上传在测试中只触发一次模型。它不等于外部模型调用或计费严格 exactly-once。
模型已执行而结果尚未记录时依然存在不确定窗口。显式 retry-analysis --confirm-uncertain 可能产生第二次费用，系统会保留这个区别。

本地所有接收入口仍共享操作系统和磁盘，不是三个独立故障域。磁盘故障可使全部本地入口不可用；若 sender 队列所在存储仍可用且任务尚未提交，已授权远程可接手。
若整台 Mac 或截图进程停了，远程服务不能继续替这台电脑截屏；未上传图片不会自动变成远程备份。
没有实现自动跨独立集群转移已进入模型执行的任务，没有虚构跨机器的统一租约服务。

六、显示接回做了哪些实际改动

恢复 capture-exclusion-demo/CaptureExclusionDemo.swift、Info.plist、build.sh 和 README。
原生 App 新增 --lanshot-display-dir /绝对路径，或读取 LANSHOT_DISPLAY_DIR。没有指定时保留原 P0 文件读取兼容，但旧方式没有新协议显示回执。
新方式读取同目录的 latest_state.json 与 page.txt，写 display_ack.json、overlay_status.json 和原生菜单请求 capture_request.json。

latest_state.json 含 schema、stream_id、version、at、profile、current、text、backend。
bridge 优先定位用户当前任务，再向该任务固定的接收集群取结果；远程完成结果也能显示，不依赖本地 receiver 恰好有同样答案。
失败的新截图尚未入队时，bridge 也会读取 sender 的捕获失败状态，不继续把旧成功答案当作本次结果。
上一次结果只以“不是本次答案”的标识出现。没有新状态或状态过期时原生窗口显示等待/缓存告警。
文本应用到主线程后才写匹配的 stream_id/version/task_id 回执；这证明应用了该版本文本，不证明人已看见，也不证明系统第三方采集行为。

原生菜单的手动截图采用请求 UUID 去重；超过60秒的旧点击不在重启后重播。
Sender 写配置 display_dir/page.txt，桥接和原生窗口使用相同目录。F23/F24、移动和显示切换不再写另一个旧目录。
停止管理器只对自己的显示目录发 quit 命令，不用 killall 终止所有原生窗口实例。
启动前校验新 App 的 LanShotDisplayProtocol=1；旧二进制不会被当作已支持新状态目录。
build.sh 先在临时目录编译、签名，成功后备份旧 App 再替换。编译失败不先删除旧 App。

九、在Mac上怎么启动这个修订版本

先在独立解压目录执行安全演练，核对原生源文件；不要把本包直接覆盖现有P0。
保留旧代码和状态备份，通过旧系统自己的控制入口停止旧sender监听器；新管理器不会替你批量杀旧进程。
在Mac上编译：
sh ../capture-exclusion-demo/build.sh
sh build_native_redactor.command

在screenshot-sender目录创建新配置：
python3 manage_services.py configure --mode redundant
python3 manage_services.py start --dry-run

首次配置默认8788/8789、profile=default、enabled=false，不会启动。若原P1 settings.json已存在，拒绝覆盖。
需要保留旧P1设置时，显式选择新的 --settings 和 --state-dir；之后所有管理/诊断命令使用同一settings路径。
诊断程序的 --settings 写在子命令之前：python3 diagnostics.py --settings /绝对路径/settings.json status。
管理程序的 --settings 写在子命令之后：python3 manage_services.py start --settings /绝对路径/settings.json --open-display。

钥匙串模型Key：服务com.lanshot.bailian、账户DASHSCOPE_API_KEY。可选本地API令牌/语音参数在服务com.lanshot.p1下。只导出终端环境变量不代表launchd子进程拥有同样配置。
授予实际执行程序需要的系统权限；blocked_words有内容时原生脱敏程序必须能工作，不能用关闭脱敏来提高成功率。

准备完成后显式启动：
sh start_assessment.command
python3 diagnostics.py status
python3 diagnostics.py routes
python3 diagnostics.py capture
python3 diagnostics.py queue
python3 diagnostics.py export --output ./diagnostics-new.zip

单体模式在另一套停用配置中以 configure --mode monolith 建立；仍有原生显示和display_bridge，不需要HTTP receiver。
这些模式配置共享固定的com.lanshot.p1.*标签，设计为单次一个活跃安装。不能同时启用两套不同settings抢同样标签；管理器会检查安装归属。

笔试/语音配置显式指定 --profile written --prompt /绝对路径/written_prompt.txt，并使用对应settings运行start_written.command。它不默认启动原生显示；语音Key和服务可达性仍需真机验证。

停止：python3 manage_services.py stop。只停止本修订管理的角色，保留状态与原数据；确认未停完会报告degraded。
