# 开发记录

## 2026-09-16

- 截屏和面试模式接入同一个百炼知识检索配置；增加双击配置入口、本地 OCR、超时降级和每轮检索留痕。
- 面试回答默认切换到官方 `gemini-3.8-flash` 中等推理，支持本地 7890 代理自动发现，并保留 GLM-5.3 故障降级。

## 2026-09-15

- 原生菜单增加运行期模式切换和面试会话管理；模式切换通过现有 Python 控制进程完成互斥交接，会话上下文按持久 ID 隔离且不删除旧历史。
- F23 提问改为后台队列生成答案，下一轮 ASR 不再等待模型返回；悬浮窗启动增加单实例锁，消除重复菜单栏图标。

## 2026-09-14

- 运行时选择器增加 Homebrew `python@3.10` 至 `python@3.14` 的 Apple Silicon 与 Intel 固定路径；另一台 Mac 即使保留系统 Python 3.9，也只需并行安装 `python@3.12`。
- 增加另一台 Mac 的一键安装入口：检查 macOS、Python 和 Swift 工具链，写入本机钥匙串、编译原生程序，并启动语音模式到不录音的待机状态。
- 所有双击启动脚本通过统一运行时选择器定位 Python 3.10 以上版本，避免 Finder 启动时误用 macOS 自带 Python 3.9。
- 语音模式不再依赖另一台 Mac 上不存在的截屏模式配置；没有 Apple Development 证书时安装器可生成一次性本地签名，并明确提示重新编译后的权限影响。

## 2026-09-12

- 语音模式启动语义改为 `idle`：只打开控制与显示界面，必须由用户明确点击“开始采集”才启动双路录音和实时 ASR。
- 语音模式现在与双路采集一起启动和停止不可捕获的原生悬浮字幕，并将悬浮窗进程纳入模式健康检查。
- 修正语音模式仍检查旧 `LanShot2AudioCapture.app` 路径的问题，统一指向最终稳定身份 `LanShot Voice Capture.app`，避免每次切换模式都误判缺少程序并重复构建、重签名。
- 合并 LanShot 截图能力与 LanShot2 双路音频能力，新增统一模式控制器。
- 截屏模式与语音模式严格互斥，切换前先停止旧模式。
- 停止旧模式后轮询实际进程状态；超过等待时间仍未退出时拒绝启动新模式，避免短暂重叠和快捷键争用。
- 增加原生模式选择入口、独立切换入口、全部停止和状态查询。
- 检测 GodHands 进程并拒绝启动冲突模式。
- 模式状态原子写入本地文件，不保存凭据。
- 真实切换验证通过：截屏模式进入 `ready`，状态检测只发现截屏进程；执行全部停止后，语音与截屏进程均为 false。语音模式因 `LanShot2 Audio Capture` 尚未获得屏幕与系统音频录制权限，本轮没有绕过权限启动。
