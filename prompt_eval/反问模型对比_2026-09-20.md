# LanShot 反问模型实测｜2026-09-20

结论：先保留 Gemini 3.8 Flash HIGH 作为默认候选，DeepSeek 4.1 Flash HIGH 作为对照与备选。这个结论针对“从面试记录中挑选值得问的问题”，不是通用模型排行榜。推荐依据是选题、上下文适配和表达，不是单纯速度。两者仍有前提表述、选题排序等问题，不能把这次回放结果等同于现场可无审查使用。

本轮完成了独立 API 回放和 Prompt v2/v3 调试，没有切换应用默认模型，没有改正在开发的生产文件，也没有做悬浮窗端到端验收。反问入口的调用缺参问题在收尾时再次读取确认仍存在。

## 实测范围

共46次真实生成请求，涉及5个模型、8个常规配置，另有2次GLM参数诊断。包括旧Prompt基线2次、v2对比35次、v3回归9次。没有把规则兜底、Mock或模型自评分当作模型能力结果。

使用6份真实会话片段，不是上一轮10场记录全部完成测试。先在教育Agent、业务开发TL、广州Agent/RAG三份片段上进行同Prompt横向比较，再补Agent基础、达人推荐、缺失面试官语句的政企记录。每个配置每个样本只采样一次，没有置信区间，也不能据此宣称统计显著优于其他模型。

输入剔除了历史模型回答、复盘、纪要，以及实际反问开始后的内容。两路录音按原文采集批次保留，不能把一次采集中的多句转写当成多轮追问。模型返回名称与请求名称一致，测试不自动换模型或回退规则。

DeepSeek Pro的单次成功耗时为129.204秒和204.419秒；超时是本地测试预算终止，不代表它最终一定不能回答。鉴于本任务没有观察到明确质量增益，暂不优先选它，而不是仅因速度慢就淘汰。

GLM最初只开启thinking并传thinking_budget、没有显式设置reasoning_effort，两次分别耗尽8192和16384输出预算，没有形成有效问题。后来明确设置low/high，均正常。HIGH三份分别20.512、22.667、35.423秒。因此最初失败应归入参数/预算诊断，不能说成“GLM模型不行”。LOW模式三份报告的reasoning_tokens分别169、0、0，不能因开关为true就认定每次都进行了大量思考。

## Prompt改变了什么

旧Prompt使用“没答好加连续追问优先”的硬规则，而且没有明确限制候选池长度。教育面基线中，DeepSeek给9条，Gemini HIGH给4条，普遍带长前缀和自贬。这不是违反旧Prompt，而是旧Prompt本身不符合最终需要。

v2改为最多3条、只依据当下真实记录、保留逐行证据、不要把所有技术题变成团队线上实践题。v3再限制说话人归因、条件与确定性、候选人第一人称、重复主题和明显转写错词。引用必须保留原词，问题正文则可以在上下文明晰时把IG、RAP等改回RAG。

v3不是在所有模型上重跑。Gemini HIGH回归6份，DeepSeek Flash HIGH回归TL、达人推荐、政企3份。主横向表仍使用统一v2，避免把不同Prompt的成绩混成一个排名。

## v3回归结果与保留问题

Gemini HIGH：6/6返回严格JSON，共17条问题，41/41条引用能在对应原文行匹配。完整耗时12.231至20.102秒，均值16.22秒。达人推荐只给2条，没有强行凑第三条。

DeepSeek Flash HIGH：3/3返回严格JSON，21/21条引用匹配。完整耗时30.199至73.012秒，均值48.55秒。样本集合不同，这个均值不能直接作为与Gemini六份回归的公平速度比。

人工核查仍发现以下问题。

Gemini在广州面写“我目前确实容易出现错乱”。原始会话第9批次、L433—L436的候选人表述是：如果两人上传同一份公共文件，可能会出现问题。模型把条件性风险扩大成当前明确状态，且自己的证据数组只引用了面试官L93、L337、L340，没有引用候选人这段条件。不是完全捏造风险，但不能替用户说得更确定。

Gemini在TL面把岗位匹配顾虑放到第三条，前两条是RAG边界和岗位分工。选题没有完全偏离，但从“获得对自己有用的反馈”这一目标看，排序仍可改善。

DeepSeek在政企回归中选了迭代停止、检查间隔和混合检索，没有选择代码编辑设计。问题本身能交流，但“这场最值得问什么”仍需人工判断，不能靠引用通过代替价值评估。

在更早的v2压力样本中，Gemini LOW写过“您之前提到了另外的解法”，而可用原文并没有面试官的完整解法发言。即使6条引文全部匹配，仍可能发生这种语义归因错误。

## 接入状态与必要修复

当前lanshot2/audio_service.py的generate_and_save_reverse_questions将系统提示与对话拼成一个字符串，再调用client.ask(prompt)。但实际客户端签名要求ask(question, prompt, history=None)。本轮用inspect绑定验证得到missing a required argument: 'prompt'，收尾重新读取仍未改。异常会被捕获后进入规则兜底，因此界面有结果不等于已经调用模型成功。

该函数只显式读取timeline.jsonl或当前两路文本。没有在这个函数中按conversation_id读取并组装conversation_history。需确认整场覆盖、跨会话隔离和未提交片段；本轮未完成这些集成检查。

推荐配置单独保存在reverse_questions_recommended_config.json，没有接入应用。Gemini为HIGH、maxOutputTokens=12288；DeepSeek为enable_thinking=true、reasoning_effort=high、max_tokens=16384。测试使用150秒socket timeout与210秒流总预算。这些是本轮实测设置，不是所有业务的最佳参数。

反问调用不应直接沿用普通作答客户端的4096输出预算与20秒超时。必须检查finish reason、空结果和JSON完整性。规则兜底应标记为降级，不能显示成模型成功。对外展示只保留问题和短主题，依据、分数、引文留在调试记录；问题前提的语义检查不能由引文字符串匹配替代。
