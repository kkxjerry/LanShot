# RAG 接入留痕（2026-09-16）

## 目标

在不改变 LanShot 截屏/面试双模式、快捷键和回答模型的前提下，接入阿里云百炼已发布的知识检索服务。

## 实现边界

- 使用官方 `POST /api/v1/indices/knowledge/search`，Endpoint 只能由验证后的 Workspace ID 推导，配置不允许注入自定义 URL。
- API Key 仍使用 `com.lanshot.bailian / DASHSCOPE_API_KEY` 钥匙串项，知识库配置和日志不记录凭据。
- 面试模式使用已封口的系统声音和麦克风文字作为查询。
- 截屏模式使用 macOS Vision 本地 OCR 生成查询；图像仍只进入原有的截图模型流程。
- 检索不是回答成功的必要条件。任何检索或 OCR 错误仅记录类型，随后继续无 RAG 的原模型请求。
- 召回内容标记为不可信事实资料，防止文档中的指令改变原提示词或输出格式。

## 本地记录

- 公共配置：`~/Library/Application Support/LanShot/knowledge.json`。
- 面试模式：`~/Library/Application Support/LanShot2/audio/knowledge_status.json` 及每轮 `*-knowledge.json`。
- 截屏模式：接收端 `latest_knowledge.json` 及七天历史中的 `*.knowledge.json`。
- 记录内容包含查询、召回切片、来源、分数、请求 ID 和耗时，不包含 API Key。

## 已验证与待验证

- 已用现有钥匙串凭据验证用户提供的 Workspace/Agent 组合：HTTP 200，服务可达。
- 当时通用测试查询召回为 0，因用户正在准备数据，不将空召回视为实际效果验收。
- 代码单元测试覆盖配置校验、有召回、空召回、网络失败降级、双模式注入和本地留痕。
- Python 回归共 240 项通过；原生 OCR 在实际截图上完成编译与中英文提取验证。
- Swift 旧套件共 81 项，79 项通过；仍是与本次 RAG 无关的两个已知失败：NIO `EmbeddedEventLoop` 线程误用超时，以及旧控制页文本断言不匹配。
- 单题验收后仍需批量验证召回率、分数分布、端到端延迟和回答忠实度。

## 首次真实数据验证

- 用户导入数据后已开启知识检索。评测只向被测链路发送 `questions_only.jsonl` 中的问题与范围，模型回答后才读取参考答案核对。
- `QA003` CODA 链路问题原始返回 5 个明显不相关片段，分数仅为 0.3097–0.3397。因此客户端新增默认 `min_score=0.5`；重测后该问题为空召回并正确走原模型降级。
- `QA069` 验证集规模问题召回 5 个片段，分数为 0.8112、0.8094、0.7985、0.6390 和 0.6350；检索端到端 628ms，回答模型 2525ms，总计 3153ms。
- `QA069` 回答正确包含 10,722 篇文档、500 总题、470 道可评估文档检索题，并正确区分 Hit@10 与答案准确率；未出现“自建 500 题”或“全部指标都用 500 作分母”的严重错误。对照待用户核实的参考答案，唯一可进一步明确的点是直接说明这是公开基准而非自建数据。

## 回答模型切换验证

- 同一 `QA069` 问题上，GLM-5.3 低推理生成耗时 2525ms，但输出被用户判定为报告式、信息铺开过多。
- 官方 `gemini-3.8-flash` 高推理生成耗时 9583ms，使用 690 个思考 Token，仍然偏报告式，不适合现场快速回答。
- 增加“候选人口语、事实题 80–180 汉字、只回答被问内容”约束后，Gemini 中推理生成耗时 4908ms，输出明显缩短。
- 最终运行配置为 Gemini 中推理、最多 3 个召回、最低分数 0.5。真实组合请求命中 3 个片段，检索 801ms，模型 5329ms，总计 6130ms，使用 Gemini 且未触发备用模型。
- 真实运行中发现宿主存在过期的 `DASHSCOPE_API_KEY` 环境变量，曾覆盖钥匙串正确凭据并造成 HTTP 403。macOS 现强制优先读取钥匙串，环境变量只在钥匙串无值时作为备用。
- 检索失败的一次 Gemini 请求曾编造未提供的“线上日志”和“三千篇文档”。策略现改为分层降级：通用题与开放题继续直接回答；项目题可提供条件性通用设计，但不得冒充已实现事实；精确个人数据只说明统计口径和验证方法，禁止给出替代数字、区间或数量级。最终答案不暴露索引、召回或内部降级状态。
- 强制空召回实测：“如何设计高并发任务队列”正常返回完整方案；“线上用户数与峰值 QPS”仅保留具体数字，同时返回日活、并发、网关监控与压测等统计和验证方法，没有生成任何假设数值。
- 十题音频实测后将检索 Query 与存档 Question 分离：存档保留双路原文，检索仅取面试官声道的最后一道题，去掉题号、开场白与重复口头语，并将 `codah` 归一为 `CODA PaiCLI`。

## Gemini Developer API 封装

- 用户提供的 Gemini Developer API Key 已通过 `models/gemini-3.8-flash` 检查，HTTP 200；凭据只保存在 `com.lanshot.google / GEMINI_API_KEY` 钥匙串，未写入源码、配置或日志。
- 同一 `QA076`、同一高推理和同一 7890 xray 代理下，Agent Platform 流式首个可见文字为 12,633ms，完整生成为 14,643ms；Developer API 分别为 4,909ms 和 6,028ms。
- 正式回答端点改为 `generativelanguage.googleapis.com/...:streamGenerateContent?alt=sse`，`thinkingLevel=HIGH`。每个可见 SSE 分片都原子更新 `answer.txt`，原生悬浮窗保持 0.35 秒轮询，因此可在完整答案之前显示已生成文字。
- 流数据设置 4MiB 上限，单次网络等待上限 20 秒；解析错误、网络失败或 Gemini 错误时自动切换到 GLM-5.3。会话留痕新增首字、完成耗时、流事件数和是否降级。
- 正式封装完成后再次实测 `QA076`：RAG 892ms，Gemini 首次可见回调 5789ms，共 12 次文字回调，模型完成 6852ms，端到端 7771ms；实际使用 Developer API 高推理且未触发 GLM 降级。
- 后续真实面试记录中，Gemini 高推理多次完整生成为 7.6–8.7 秒，一次首段 18.7 秒、完整 19.7 秒；正式默认因此调整为 `thinkingLevel=MEDIUM`，保留 Developer API、SSE 流式、7890 代理和 GLM 降级链路。
- 切换后的单次 `MEDIUM` 对照首段 10.5 秒、完整 11.6 秒，表明供应商延迟存在明显波动，不应用单次样本声称中等推理必然更快；本次调整的目标是限制极端思考预算，后续仍需统计多次 P50/P95。
